# Журнал изменений CDM и Metabase

## 20.10.2026 — реализация

- Добавлена повторяемая схема CDM с зерном каждой таблицы; источник — только DDS.
- Добавлен загрузчик с согласованным read-only снимком DDS, проверкой трёх публикаций, пересчётом истории, отпечатком источника, атомарной заменой и отдельной диагностикой запусков.
- Добавлены CLI, адаптер Airflow и задачи `publish_dds` → `publish_cdm`. Выборочные STG запуски пропускают обе публикации; ручное расписание сохранено.
- Добавлены роль `cdm_reader` и локальный сценарий Metabase API для источника, восьми вопросов и трёх дашбордов с семантически допустимыми фильтрами.
- Исправлен режим исполнения `docker/postgres/init/10-init.sh`: на новом Mac отсутствие бита исполнения остановило первый старт аналитической БД. Схемы и служебная БД были созданы повторным запуском init-скрипта без удаления volume.

- `python3 -m compileall -q src/cdm scripts/provision_metabase.py dags/github_issues_stg.py` — успешно.
- `python3 -m unittest discover -s tests/cdm -v` — быстрый тест успешен; интеграционный запускается отдельно.
- Три теста CDM, включая интеграционный на PostgreSQL 16 и девяти Issues, — успешно. Подтверждены отказ Airflow при неполном результате DDS, повтор без изменений, пересчёт изменённой истории, полночь, нулевой знаменатель, медианы, текущие метки и отсутствие автора.
- Тот же тест принудительно прерывает замену строк CDM после начала транзакции: опубликованный `run_id` и дневные строки сохраняются, затем исправленная история публикуется успешно. Ошибка проверки исходной партии после read-only снимка отдельно записывается в `load_runs` как `failed`, активная публикация не меняется.
- Эталонный `docs/sql/CDM_REFERENCE_METRICS.sql` выполнен в `REPEATABLE READ READ ONLY` на тестовой базе: 4 новых в марте, 8 созданных к срезу, 2/6 закрытых/открытых, общая доля 0,25, медианы 10 и 20 дней, повторные открытия 2/4, 8 связей с метками для 6 Issues.
- 13 тестов DAG в образе Airflow 3.3.2 — успешно, включая пропуск DDS/CDM для выборки `sample`.
- Compose после восстановления init-скрипта: все долгоживущие сервисы healthy.
- Повторный запуск `scripts/provision_metabase.py` вернул те же IDs источника, коллекции и трёх дашбордов. Все восемь SQL-вопросов выполняются на рабочем CDM. Фильтры репозитория и диапазона дат проверены на каждой исторической карточке; фильтр даты первого закрытия — на месячной медиане, репозиторий — на двух карточках меток. - После рабочей загрузки повторно проверены `init-db` (`schema_ready`, `reader_ready=true`), `docker compose config --quiet`, компиляция Python и `git diff --check`. Права `cdm_reader`: чтение `cdm.issue_day` разрешено, `USAGE` схем DDS/STG и чтение `dds.issues` запрещены. Локальный `.env` игнорируется Git.
